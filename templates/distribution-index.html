Build and update Canvas courses with assistance from AI and deterministic scripts.

This toolkit converts editable course prose, configuration files, and test materials into Canvas pages, assignments, discussions, rubrics, quizzes, printable tests, and complete IMSCC course packages. It supports guarded Canvas API scripting, deterministic IMSCC import workflows, and optional AI access through a web chat, command-line agent, or Canvas MCP. Course targeting, validation, backups, link checks, and quality-assurance records help keep changes reviewable and confined to the intended sandbox.

First run on Mac for command-line operation

Complete these steps when you are ready to validate files, build PDFs or IMSCC packages, or use guarded Canvas automation from the local command-line toolkit.

  1. Install uv.
  2. Double-click setup-after-move.command. This recreates the pinned deterministic environment.
  3. Double-click commands/initialize.command and paste the unpublished sandbox course URL from the browser bar. This establishes the one course target and updates command IDs.
  4. Review course/course.config.jsonc. It is the central institution and course configuration.
  5. Double-click commands/start-server.command, enter your Canvas token privately, and leave that window open.

Start in a disposable, unpublished sandbox. The local API server refuses every course except the initialized sandbox.

Testmaker

This toolkit’s Testmaker tool turns one editable test source into Canvas quizzes and deterministic printable PDF forms with answer keys. Testmaker accepts Markdown, plain text, and DOCX; it supports multiple-choice and written questions, randomized take-N pools, and version-specific paper questions. Validation checks structure before generation or guarded Canvas synchronization.

Real questions, answers, generated forms, and backups remain under excluded private/ and out/ locations. A public toolkit distribution contains safe examples, authoring documentation, parsers, validators, and builders.

Assignment and rubric testing

A configurable Mistral harness completes assignment instructions from several literal student profiles, grades each simulated submission against a rubric, and reports ambiguous requirements, unsupported grading judgments, and instruction–rubric mismatches. The process provides diagnostic examples for human review. Simulated grades are never student grades.

Only deliberately selected source files are sent to Mistral. Keep student data, real student work, accommodation information, answer keys, and confidential materials out of API runs.

Course-specific values

commands/initialize.command handles the course URL, Canvas host, course ID, institution name, homepage, policy domain, and library resolver. Edit course prose only under course/content/. The object map is course/course-manifest.json; all discovered course and institutional links are organized in course/links-manifest.json.

For values that require research or interpretation, ask an AI agent to use $configure-canvas-course from skills/configure-canvas-course/. The skill directs the agent to research authoritative institutional sources, update the central manifest and canonical prose, refresh links, and run guarded verification. Distribution-only settings remain in commands/build-distribution.config.jsonc; portability markers remain in commands/portability-audit.config.jsonc.

AI in a CLI

Open the unzipped folder as the agent workspace. Tell the agent to read this page, README.md, and the relevant config schema. Let it edit configs and run deterministic dry runs. Require the sandbox guard and a reviewed plan before live writes.

The CLI is the portable contract. macOS launchers are a thin convenience layer.

AI through Canvas MCP

The optional, independently maintained Canvas MCP is pinned at {{MCP_VERSION}}. On macOS, run commands/setup-canvas-mcp.command. Use MCP for discovery and small reviewable actions. Use scripts or IMSCC for repeatable bulk work.

Layered quality assurance

  • Run local tests and config validation.
  • Inspect Canvas migration warnings.
  • Check object counts and publication states.
  • Confirm rubrics and quiz questions.
  • Validate assignment-group weights.
  • Run Canvas Link Validator.
  • Check internal slugs, IDs, and fragments.
  • Run provider-aware external link checks.
  • Open every video in a private browser.
  • Use Student View.
  • Run accessibility checks and manual review.
  • Repeat QA after course copy or import.

The link checker uses Vimeo and YouTube oEmbed. This catches pages that return HTTP 200 while the video itself is unavailable. Read the full QA checklist.

Dependencies and support

macOS is supported and tested. Linux supports the Python CLI with manual setup. Windows CLI support is experimental. See platform details. The deterministic environment—including the loopback-only Waitress production WSGI server and PDF testmaking dependencies—is pinned by uv.lock. MCP has a separate pin under mcp/. The ZIP includes LICENSES.md, sbom.json, and DISTRIBUTION-MANIFEST.json.
